# DESIGN.md — PrimeNG Aura Noir/Slate trading desk

Components render at PrimeNG Aura preset defaults customized once as `NoirSlate` (`src/app/app.config.ts` via `definePreset(Aura, …)`): primary maps to the zinc scale (noir monochrome variant), light + dark surfaces map to slate, `darkModeSelector: '.dark'` shared with the existing dark toggle. The dark scheme also lifts Aura's global `text.mutedColor`/`hoverMutedColor` from the slate-500 step to slate-300/200 so secondary copy clears AA on the slate-950 desk — a semantic-token mapping in the same sanctioned layer as the primary/surface/highlight mappings, not a per-component override. No per-component color, palette, or motion overrides; the one sanctioned exception is geometry — table cell density (`padding-block`/`padding-inline` in `features/trades/trades.css`), the Journal calendar's compact Net-tag chip (`font-size`/`padding` in `features/journal/journal.css`), and layout utilities PrimeNG's own selectors would otherwise outrank (the `.text-right` re-assert in `src/styles.css`) may be tuned so the money rail fits the first screen. A single-line field's height belongs to FloatLabel's `in` variant (`padding-block` inside the field), not to a pinned control height: the label floats inside the field, so pinning the box to `--oj-control-h` would push it out. Source: v21 Noir + Surface theming docs and PrimeNG MCP `chart`/`datepicker`/`drawer`/`toolbar`/`select`/`button` APIs.

Five routes, one page goal each (statements pinned in `PRODUCT.md`), one shell. Configuration lives only on /settings, exiled from the Operate pages by ADR-0007. Shell and surfaces use Tailwind layout utilities plus PrimeNG structure:

- shell: `p-drawer` (mobile, `lg:hidden`) + static `aside` (`w-80`, the Aura drawer width, `hidden lg:flex`, pinned with `lg:sticky lg:top-0 lg:h-dvh lg:self-start`) drive the same `navGroups` source with plain `routerLink` anchors grouped Overview / Workspace / Configuration and 12px uppercase group labels; the rail's nav scrolls (`min-h-0 flex-1 overflow-y-auto`) and both navs share one foot template — `p-select` Portfolio switcher beside the unfiltered Net P&L — so portfolio scope stays reachable on every long page. Active route on `bg-highlight text-highlight` with `aria-current="page"`; at ≥lg the rail opens with an identity row — avatar, app name, and the icon `p-button` dark toggle — and the `p-toolbar` header is mobile-only (`lg:hidden`), carrying identity, the drawer trigger, and the same toggle (the wallet icon and toolbar Net chip stay retired; ADR-0009). `p-dialog`/`p-confirmdialog` only inside /settings, while `p-toast` also carries the Trades save confirmation at bottom-right and caps to `calc(100vw - 2.5rem)` below 480px so it clears the 20px offsets; page identity from `app-page-hero` (title + subtitle + one lucide icon + projected headline chips) on every route.
- data: sortable `p-table` everywhere (Trades history with paginator + CSV export in the history-card header + row expansion for execution/process detail and the `{rule text, followed}` snapshot; Dashboard's five-row recent preview with View all; Journal day detail; Analytics breakdowns/time-patterns/compliance), `p-chart` line for the balance curve and bar for the "Top 10 by |Net|" breakdown (runtime `chart.js`), `p-datepicker` for filter range + Guard stop time (`timeOnly`), `p-inputnumber` for balance/Guard/count/price/quantity editors, `p-select` for every categorical axis (Market/Side/Setup/Emotion/Mistake/Grade/dimensions/filters), `p-checkbox` Playbook checklist, `p-textarea` notes, `p-chip` Tags, `p-tag` Net/Grade/Compliance/Guard/count states, `p-message` validation + Guard warnings, definition-list KPI bands (tabular numerals) in place of tile strips. The Trades filter bar is one flat row of compact Aura controls at ≥1440 (`desk`, the named 90rem breakpoint) on proportional tracks with no fixed control widths, and a native `Filters (n)` disclosure below (date range counts as one axis; icon-only Reset appears only while filtering). The log form groups Trade & execution above Process with `p-floatlabel variant="in"` per field and three-column grids from `lg` (the two required grids run five columns from `xl`, the optional tail stays three); below `lg` the optional tail sits behind a `More details` in-place disclosure, the phone hero action is full width, and from `sm` the form's action row pins to the viewport bottom so Save stays reachable on a long form. The hero action renders only while the Portfolio holds a Trade or the form is open; an empty Portfolio's single first-use CTA lives in its onboarding panel.
- domain exceptions with PrimeNG around them: the Journal month calendar stays a custom UTC close-date grid (close-date bucketing, neutral cells with the day Net in an Aura `p-tag`, gain `+` prefix, flat `0`, breach-only Guard icon, day selection have no PrimeNG equivalent); the log-form timestamps stay `pInputText` datetime-local (reactive form models UTC ISO strings) and carry a placeholder only to trigger FloatLabel's `in` float, since browsers ignore placeholder text on date/time inputs.

## Token contract

The only color sources in templates are the PrimeNG Aura scales that `tailwindcss-primeui` exposes as Tailwind utilities, plus component tokens:

- surface scale: `bg-surface-0`, `text-surface-700`, `text-surface-600 dark:text-surface-300` for secondary copy, `border-surface-200 dark:border-surface-700`, `hover:bg-surface-100 dark:hover:bg-surface-800`; `src/styles.css` applies the same pair to `body`.
- primary scale: `text-primary` / `bg-primary` from the NoirSlate primary (zinc) mapping.
- selection and tinting: `bg-highlight` (Aura `--p-highlight-background`/`-color`) for the active nav item and the selected calendar day — never a bespoke tint. Every `bg-highlight` surface carries its token foreground `text-highlight` (static class, `routerLinkActive`, or `[class.text-highlight]` beside the `[class.bg-highlight]` binding): the light-theme highlight background is near-black, so `bg-highlight` alone renders an unreadable black pill. Enforced by `design-tokens.spec.ts`.
- semantic state: component `severity` — `p-tag` `success`/`danger`/`warn`/`secondary` for gains, losses, Guard status and counts, `p-message severity="error"` for inline validation. No `text-success`/`text-warning`/`text-destructive` classes.
- shared pill: `.oj-pill` (`src/styles.css`, `@layer components`) is the one style for every user-value pill (Tags in the history table, Vocabulary lists in Settings) — `rounded-full`, `px-2.5 py-0.5`, `text-xs font-medium`, `bg-surface-100 dark:bg-surface-800` fill with `text-surface-700 dark:text-surface-200`; it composes only Aura-scale token utilities, so the token contract still holds. Templates name the class instead of re-typing utilities, which is how the pill drifted `px-2`/bordered on one page before it existed.
- type scale: page titles use `text-2xl` (24px), section and card headings `text-xl` (20px), and body copy, subtitles, form/filter labels, nav items, KPI-band rows, and table content cells `text-base` (16px). Two supporting steps sit below body: metric labels and other metadata at `text-sm` (14px), and nav group labels plus `.oj-pill` chips at `text-xs` (12px). Carve-outs: large KPI display numbers (the Dashboard Net P&L headline, the Journal Month Net / Balance values) keep their display size, and PrimeNG component-internal text (`p-tag`, button/input labels, table cell default) renders at the Aura preset. Body copy sets `text-wrap: pretty` so no paragraph strands a single word on its last line.
- dark mode: class-based on `documentElement`, shared by PrimeNG (`darkModeSelector: '.dark'`) and Tailwind via `@custom-variant dark (&:where(.dark, .dark *))` in `src/styles.css`, so `dark:` utilities follow the toggle and not the OS preference.
- canvas charts: `p-chart` axis ticks and gridlines read the preset's `--p-text-muted-color` / `--p-content-border-color` through the same live-variable reader as the bar and curve colors, so both schemes clear AA; chart options name no literal palette.

The shadow semantic-token layer inherited from the retired design language (`--background`, `--foreground`, `--muted-foreground`, `--card`, `--popover`, `--accent`, `--destructive`, `--success`, `--warning`, `--border`, `--input`, `--ring`, `--sidebar-*`, its `@theme inline` `--color-*` mappings and its hand-written `.text-success`/`.text-warning`/`.animate-fade-in-up` utilities) is deleted from `src/styles.css`. No template may name it.

The retired idioms never return: kickers/eyebrows, gradient hero/header washes, `rounded-[28px]` hero/card, stat-strip repetition as decoration, `hover-lift`, `animate-count-up`, `stagger-*` delays, colored `border-left` callouts, glass decoration. No hex colors, `rgb()`, `oklch()`, hard-coded Tailwind palette shades (`bg-red-500`, …), arbitrary color values (`bg-[#…]`), `style=` / `styleClass=` / `[style]` / `[class]` overrides in any `*.html` template.

Icons: every app-authored icon is `@ng-icons/lucide` (`ng-icon`, registered per component through `provideIcons`), including inside PrimeNG buttons via the `icon` template slot. Size comes from `ng-icon`'s `size` input wherever it must differ from 1em — the component's host CSS sets `width: var(--ng-icon__size, 1em)` outside Tailwind's layers, so `size-*` utilities lose. PrimeIcons appear only where PrimeNG renders inside its own components (`p-sortIcon`, the `p-datepicker` trigger).

`src/app/design-tokens.spec.ts` polices the prose above with eight patterns — hard-coded palette, retired shadow tokens, kicker/eyebrow idioms, `animate-fade-in-up`, bespoke `style`/`styleClass`/`[class]` overrides, the deleted `app-quick-stats` tiles, app-authored PrimeIcons, and the retired SaaS template idioms. Each pattern is proven three ways: it fails on a retired-idiom fixture, it accepts the Aura replacement-idiom fixture, and it finds nothing in any template scanned through `import.meta.glob('./**/*.html')` (28 tests green).

## Notes kept while building

- Tabular numerals in tables and KPI bands; chronological time-pattern rows (Monday→Sunday, 00→23, Intraday→Swing) with all fixed rows present even when empty.
- Trades history reads review-first (Close, Asset, Side, Net, R, Setup, Grade, Compliance, Tags); the execution fields (Open, Market, Quantity, Multiplier, Entry, Exit, Gross, Fees, Stop, Take, Risked) and the process extras (Emotions, Mistake, Chart, Notes, Playbook Rule snapshot) sit in each row's expansion. CSV export sits in the history card header, not the filter row. Below `sm` the Close date column folds into the row expansion so Asset, Side, and Net stay on the first screen.
- The filter bar stays one flat row at ≥1440 (`desk`, a named 90rem `@theme` breakpoint because Tailwind emits arbitrary `min-[1440px]` variants before `lg`) with proportional tracks and no pinned control widths, and collapses to a native `Filters` / `Filters (n)` disclosure below, never a card or floating panel; its date range counts as one active axis and Reset is icon-only. Log-form field ids are namespaced (`log-*`) because the open form coexists with the always-rendered filter bar.
- Settings centers at `max-w-6xl` with Portfolios, Vocabulary, and Playbooks cards in two-column grids (from `xl`, where the rail leaves room). Portfolios is one flat divided list — name and text-icon rename/delete on the left, starting balance on the right — not nested rows, and Playbooks is a single-open accordion so one rule list is expanded at a time; Guards separates Daily and Weekly with labeled rules instead of nested panels, so cadence stays legible without stacking cards. Starting balance lives once per Portfolio inside Portfolios, with a read-only All anchor beside the list; under All the Guards card swaps its inputs for "Guards are set per Portfolio — select one" and shows no Guard status.
- Empty states keep the heading order honest: a page-level empty state is its own card with an `h2`, while one rendered inside a card drops the card wrapper (`embedded`) and uses an `h3`, so no page goes `h1` → `h3` and no card sits inside a same-surface card. A zero-data Portfolio uses one sibling onboarding panel on Dashboard, Trades, and Analytics: from `xl` the card pairs the copy, the single primary action, and a secondary Journal/Settings path with a labelled, number-free schematic of that page's core block; below `xl` it stacks copy-only. Trades drops the filter bar until the Portfolio holds a Trade and hides its hero action until one exists, leaving the onboarding CTA as the only first-use action.
- Dashboard is one KPI band card split into Edge / Consistency / Account sections (all nine metrics, one card shell), each section heading carrying one primary-scaled icon at 1.25rem through the `size` input; the hero's win-rate chip appears only once a Trade exists. It pairs the balance chart with a five-row Recent trades preview carrying View all to /trades side by side from `xl`; below that they stack full-width so neither card clips its table or curve.
- Analytics dimension pickers live in their card headers; each card opens with the same h2 plus supporting line, numbers right-align with tabular figures, and tables scroll locally instead of widening the page with a below-`xl` sideways hint. R-metrics run two columns from `sm` and three from `xl` so the band never squeezes at tablet. Risked Amount is unsigned capital at risk (`$200.00`), never a signed result (`+$200.00`). Its compliance empty copy distinguishes filtered-to-zero (`No Trades match this filter`), filtered scored-empty (`No scored Trades match this filter`), and a journal where no checklist was ever touched (`No scored trades yet`).
- Journal keeps one Month report card — Month Net and month-end balance with Copy in the card header, over a two-column metric grid — instead of a separate summary; day cells stay neutral and the Net tag alone carries outcome. Calendar tags trade precision for fit — cents below $1,000, whole dollars at four figures, `K` notation at five — and below `sm` the tag collapses to a severity dot while the Day detail header carries the selected day's exact Net; day detail, report card, and each cell's ARIA label stay exact at every width, and the day-detail table carries the same below-`xl` sideways hint.
- Derivations own the numbers (`.facts` is the behavioral spec): Net P&L is the single source of truth; filtered views never create a second truth; Compliance/Mistake/Grade stay process signals independent of outcome.
- Production budget is 1MB warn / 1.5MB error (`angular.json`) for the PrimeNG + `chart.js` runtime.
